# Діагностична серія: запуск разом із WSL

Це справжні вимірювання Windows EMI, але їхнє вікно починалося **до запуску `wsl.exe`** і завершувалося після його виходу. Перша O0 спроба: `ProcessWallSeconds=29.7114514`, хоча guest `compute_seconds=15.6263257`; у третій O3 спробі host window=14.1217193 s, guest compute=2.789623728 s. Межі не еквівалентні часу роботи досліджуваної програми.

Тому ця серія збережена для діагностики й **не використовується як основне порівняння енергоспоживання програми**. Її замінює окрема синхронізована серія READY → GO → RESULT після готовності Linux. Перші raw JSON і старі підсумки не змінено; наявність коректних лічильників не скасовує обмеження вимірюваного інтервалу.

Окремо в GNU time всередині WSL зафіксовано випадки, коли real elapsed менший за guest steady-clock compute або user CPU time. Причина не встановлена; віднімати ці часові джерела для визначення накладних витрат некоректно. Факт і приклади наведено в основному звіті.
