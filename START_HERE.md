# З чого почати

Практичні вимірювання виконано. Початкова й оптимізована програми дають однаковий результат. Медіанний час обчислень: **15,85 → 2,89 с**, приблизно **5,48× швидше**. Медіанна енергія CPU package за синхронізований запуск: **486,97 → 99,27 Дж**. Це енергія названого домену процесора, а не всього ПК.

1. Прочитай [звіт](docs/REPORT.md): він пояснює отримані числа та графіки.
2. Відкрий [сценарій захисту](docs/DEFENSE.md): там порядок демонстрації й команди.
3. Для розуміння коду є [опис програми](docs/PROGRAM.md) та [розбір асемблера](docs/ASSEMBLY.md).
4. [Таблиця вимог](docs/REQUIREMENTS.md) показує, що виконано і де є обмеження.

У Windows уже налаштовано Ubuntu 24.04 через WSL. Проєкт можна відкрити у VS Code; завдання **Linux: build AVX2 variants** збирає три версії, **Linux: verify all variants** запускає перевірки. Повні команди повторення є в [README](README.md).

Для здачі потрібні доступне викладачу [GitHub-посилання](https://github.com/quadroex/os-lab2-performance-image-pipeline) та власний захист: або відео з екраном, камерою й озвученням, або демонстрація на парі. Репозиторій створено приватним; перед передаванням викладачу потрібно надати йому доступ або змінити видимість.

Енергетичну частину виконано програмним способом: CPU package / DRAM під час роботи й оцінка внеску програми після віднімання фону. Такий підхід узгоджується з матеріалом за посиланням в умові; зовнішній ватметр не є обов’язковим. Треба пояснити, що виміряно саме ці домени, а не весь ПК з розетки, і що процесна оцінка має похибку. Недоступні лічильники LLC й помічену неузгодженість годинників WSL також описано у звіті.
